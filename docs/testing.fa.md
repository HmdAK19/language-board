# آزمون، استقرار و نگهداری

[معرفی](../README.md) · [تصاویر](screenshots/README.md)

## اجرای بررسی‌ها

```sh
npm ci
npm run build
npm run lint
npm test
npx playwright install chromium
npm run test:e2e
npm run format:check
```

Playwright سرور Vite روی `http://127.0.0.1:5173` را با webServer راه‌اندازی می‌کند. خارج CI می‌تواند سرور موجود را reuse کند؛ مطمئن شوید همان نسخهٔ پروژه روی این پورت اجرا می‌شود. مرورگر پیش‌فرض Chromium است و trace شکست‌ها در test-results نگهداری می‌شود.

اگر Chromium نصب نیست، نصب آن را انجام دهید یا در Windows از Edge موجود استفاده کنید:

```powershell
$env:PLAYWRIGHT_CHANNEL = 'msedge'
npm run test:e2e
```

## گزارش بررسی نسخهٔ مستندشده

تاریخ بررسی: ۲۰۲۶-۰۹-۲۳؛ Windows، Node 22.14 و مرورگر Edge از طریق Playwright.

| بررسی                         | نتیجه                     |
| ----------------------------- | ------------------------- |
| build و TypeScript            | موفق                      |
| ESLint                        | موفق                      |
| آزمون‌های واحد                | ۱۳ آزمون موفق             |
| مجموعهٔ کامل E2E با Edge      | ۲۷ آزمون موفق، بدون skip  |
| سناریوهای تصاویر، جزئی از E2E | ۶ سناریوی موفق و ۲۰ تصویر |

تست‌ها با مسیرهای فعلی، نام قابل دسترس کنترل‌ها و فرم چندزبانه هماهنگ‌اند. سناریوی افزودن زبان، ابتدا کد تکراری AR را رد می‌کند، سپس زبان جدید اردو را اضافه می‌کند و حفظ ترجمه‌های sparse و ترتیب زبان‌ها را پس از reload بررسی می‌کند.

تست‌ها ویرایش و افزودن، جابه‌جایی با ماوس و صفحه‌کلید، ذخیره‌سازی و خطاهای آن، migration، اعتبارسنجی فرم، ناوبری و layout در شش عرض را بررسی می‌کنند. بررسی فوکوس اولیه و بازگشت فوکوس دیالوگ‌ها حفظ شده است؛ Modal بعد از showModal فیلد مشخص‌شده با autoFocus را فعال می‌کند تا زمان mount شدن React مانع فوکوس نشود.

فقط e2e/documentation.spec.ts تصاویر docs/screenshots را تولید می‌کند؛ آزمون‌های responsive دیگر همان فایل‌ها را بازنویسی نمی‌کنند تا اجرای موازی باعث رقابت در تولید تصاویر نشود. سناریوی تصاویر دادهٔ اولیه، فوکوس دیالوگ‌ها و نبود overflow افقی را بررسی می‌کند؛ پوشش رفتارهای ویرایش و persistence در translations.spec.ts باقی مانده است.

## پوشش و محدودیت

آزمون‌های واحد، reducer، اعتبارسنجی، دادهٔ sparse، migration و repository را پوشش می‌دهند. برای تغییر رفتار دامنه، آزمونی با ورودی واقعی و خروجی معنادار اضافه کنید. برای رفتار مرورگر از role و label استفاده کنید؛ نام کلاس تولیدشدهٔ CSS Modules پایدار نیست.

تصاویر responsive شبیه‌سازی viewport در مرورگر دسکتاپ هستند؛ آزمون روی دستگاه فیزیکی iOS/Android یا Firefox/WebKit محسوب نمی‌شوند. screenshotهای مستندات snapshot assertion پیکسلی ندارند. تغییر ظاهر باید با بازبینی چشمی نیز بررسی شود.

## build و میزبانی

```sh
npm run build
npm run preview
```

خروجی `dist/` را روی میزبان static قرار دهید. میزبان باید مسیرهای برنامه مانند `/manage` را به `index.html` بازنویسی کند و فایل‌های assets را عادی سرو کند. preview صرفاً بررسی محلی خروجی است و سرویس production نیست.

نمونهٔ تنظیم برای میزبان Nginx با root مناسب پوشهٔ dist:

```nginx
location / {
    try_files $uri $uri/ /index.html;
}
```

برنامه فعلاً برای ریشهٔ دامنه تنظیم شده است؛ استقرار زیرمسیر به تنظیم هماهنگ base در Vite و مسیریابی نیاز دارد. تنظیم env یا کلید API برای اجرای فعلی لازم نیست. میزبانی فایل‌ها باعث مشترک‌شدن ترجمه‌های کاربران نمی‌شود؛ داده همچنان در مرورگر هر کاربر است.

پس از استقرار، بارگذاری مستقیم و refresh هر دو مسیر، فایل‌های فونت و asset، افزودن/ویرایش و refresh داده، و پیام خطای storage را بررسی کنید. پاک‌کردن cache استاتیک را با حذف دادهٔ localStorage اشتباه نگیرید.

## نگهداری مستندات

با تغییر route، schema یا فرم، سند مرتبط و تصاویر را در همان تغییر به‌روز کنید. تعداد آزمون و نتیجه را تنها پس از اجرا تغییر دهید. برای قالب‌بندی محدود به مستندات و سناریوی ثبت تصاویر:

```sh
npx prettier --write README.md docs e2e/documentation.spec.ts
```
