# مدل داده، ذخیره‌سازی و مهاجرت

[معرفی](../README.md) · [معماری](architecture.fa.md)

## ساختار نسخهٔ ۲

نمونهٔ حداقلی معتبر (دادهٔ آغازین واقعی ۸ واژه و ۳ زبان دارد):

```json
{
  "version": 2,
  "languages": [
    { "code": "fa", "label": "فارسی", "direction": "rtl" },
    { "code": "fr", "label": "Français", "direction": "ltr" }
  ],
  "keywords": {
    "order": ["word-1"],
    "byId": {
      "word-1": {
        "id": "word-1",
        "keyword": "Hello",
        "translations": { "fa": "سلام" }
      }
    }
  }
}
```

ترتیب فقط در order نگهداری می‌شود. هر شناسه باید دقیقاً یک رکورد با همان id داشته باشد؛ شناسه‌های تکراری و نام‌های رزروشدهٔ `__proto__`، `constructor` و `prototype` رد می‌شوند. نام واژه‌ها پس از trim، NFC و lowercase باید یکتا باشند. کاتالوگ حداقل یک زبان با کد canonical و یکتا، نام غیرخالی و جهت معتبر دارد.

translations از نوع `Partial<Record<Language, string>>` است. نبودن کلید به معنی ترجمه‌نشدن است. reducer مقدار خالی را حذف می‌کند؛ validator ذخیره، رشتهٔ خالی را نیز معتبر می‌داند و UI با trim آن را ناقص نشان می‌دهد. کدهای ترجمه باید در کاتالوگ موجود باشند. حد واژه و نام زبان ۸۰ و ترجمه ۵۰۰ کاراکتر است.

## قرارداد repository

`load(): { data: Dataset; warning: string }` و `save(data): void` synchronous هستند. پیاده‌سازی createLocalRepository یک تابع دریافت storage می‌گیرد تا خطاها و داده‌های مختلف قابل آزمون باشند. save پیش از نوشتن، ساختار را اعتبارسنجی می‌کند.

کلید جاری `language-board.dataset.v2` و کلید قدیمی `language-board.dataset.v1` است. اگر کلید جاری موجود باشد اولویت دارد؛ فقط در نبود آن legacy خوانده می‌شود. در نبود هر دو، seed ساخته و ذخیره می‌شود. Provider پس از mount و هر تغییر داده نیز ذخیره می‌کند. کاتالوگ و ترتیب‌ها ماندگارند؛ زبان انتخابی فقط در حافظهٔ نشست نگهداری می‌شود.

## مهاجرت و رفتار واقعی دادهٔ قدیمی

migrateStoredDataset براساس version، تبدیل‌کننده را انتخاب می‌کند. نسخهٔ ناشناخته پذیرفته نمی‌شود.

- نسخهٔ ۱: آرایهٔ واژه‌ها به order/byId تبدیل و متن‌های خالی کنار گذاشته می‌شوند. id، نام و ترتیب حفظ می‌شوند. تبدیل‌کنندهٔ فعلی انتظار فیلدهای fa/en/fr را دارد و متن en را به ar منتقل می‌کند؛ ترجمهٔ ماشینی انجام نمی‌دهد. دادهٔ v1 با فقط fa/ar/fr توسط این مسیر پذیرفته نمی‌شود.
- نسخهٔ ۲: ابتدا اعتبارسنجی می‌شود. اگر زبان en با برچسب دقیق English موجود باشد، به عربی تبدیل و مقدار en به ar منتقل می‌شود. اگر نتیجه به دلیل تداخل کدها نامعتبر شود، بارگذاری رد می‌شود.
- در مسیر دیگرِ تعمیر v2، اگر واژه و مقدار عربی در همان index با متن انگلیسی seed قدیمی منطبق باشند، مقدار عربی seed جایگزین می‌شود. این اصلاح وابسته به موقعیت است و قاعدهٔ عمومی ترجمه نیست.

این‌ها قرارداد فعلی کد هستند و برای مهاجرت عمومی هر نوع دادهٔ قدیمی کافی نیستند؛ قبل از تغییر migration باید نمونهٔ واقعی و آزمون حفظ محتوای کاربر اضافه شود. کلید legacy در جریان تبدیل حذف نمی‌شود.

## خطا و حفاظت از داده

JSON خراب، ساختار نامعتبر یا خطای خواندن باعث نمایش دادهٔ آغازین و warning می‌شود. اگر کلید **جاری** موجود ولی ناخوانا باشد، repository نوشتن بعدی را مسدود می‌کند تا مقدار اصلی بازنویسی نشود؛ ویرایش تنها در حافظهٔ نشست می‌ماند. Provider ممکن است warning اولیهٔ خواندن را با پیام ذخیره‌نشدن جایگزین کند.

اگر فقط legacy خراب باشد و کلید جاری وجود نداشته باشد، seed می‌تواند در کلید v2 ذخیره شود؛ legacy باقی می‌ماند. در خطای quota یا غیرفعال بودن storage، رابط همچنان قابل ویرایش است اما ماندگاری تضمین نمی‌شود. هیچ listener برای همگام‌سازی تب‌ها وجود ندارد؛ آخرین ذخیرهٔ هر تب می‌تواند تغییرات تب دیگر را بازنویسی کند.
