# مدل داده و ذخیره‌سازی

[معرفی](../README.md) · [معماری](architecture.fa.md)

## ساختار داده

```json
{
  "languages": [{ "code": "fa", "label": "فارسی", "direction": "rtl" }],
  "keywords": {
    "word-1": {
      "id": "word-1",
      "keyword": "Hello",
      "translations": { "fa": "سلام" }
    }
  },
  "order": ["word-1"]
}
```

`keywords` یک map با دسترسی مستقیم بر اساس شناسه است و `order` فقط ترتیب نمایش را نگه می‌دارد. هر شناسه باید دقیقاً یک رکورد با همان `id` داشته باشد. شناسه‌های تکراری یا رزروشدهٔ `__proto__`، `constructor` و `prototype` رد می‌شوند. نام واژه‌ها پس از trim، NFC و lowercase باید یکتا باشند.

`languages` می‌تواند خالی باشد. کد هر زبان canonical و یکتا، نام آن غیرخالی و جهت آن `rtl` یا `ltr` است. حذف زبان، ترجمه‌های وابسته به آن را نیز از همهٔ واژه‌ها حذف می‌کند؛ حذف همهٔ زبان‌ها همهٔ translationها را خالی می‌کند.

`translations` از نوع `Partial<Record<Language, string>>` است. نبودن کلید به معنی ترجمه‌نشدن است. کدهای ترجمه باید در `languages` موجود باشند. حد نام واژه و زبان ۸۰ و حد ترجمه ۵۰۰ کاراکتر است.

## عملیات

| Action                        | اثر                                         |
| ----------------------------- | ------------------------------------------- |
| add                           | افزودن واژهٔ یکتا و شناسه به انتهای `order` |
| edit / updateKeyword          | ویرایش ترجمه‌ها یا تمام مشخصات واژه         |
| deleteKeyword / clearKeywords | حذف یک واژه یا همهٔ واژه‌ها                 |
| move                          | تغییر ترتیب بدون تغییر رکوردها              |
| addLanguage / removeLanguage  | افزودن یا حذف زبان و ترجمه‌های وابسته       |
| clearLanguages                | حذف همهٔ زبان‌ها و تمام ترجمه‌ها            |
| moveLanguage                  | تغییر ترتیب زبان‌ها                         |

## ذخیره‌سازی

قرارداد repository همگام است: `load(): { data: Dataset; warning: string }` و `save(data): void`. کلید Local Storage برابر `language-board.dataset` است. اگر داده‌ای وجود نداشته باشد، seed ساخته و ذخیره می‌شود. Provider پس از هر تغییر، کل dataset را ذخیره می‌کند.

دادهٔ Local Storage و فایل import در مرز ورودی به‌طور کامل اعتبارسنجی می‌شوند. JSON خراب یا ساختار نامعتبر باعث بارگذاری seed و نمایش warning می‌شود. اگر مقدار موجود ناخوانا باشد، ذخیرهٔ خودکار مسدود می‌شود تا دادهٔ اصلی بدون اطلاع کاربر بازنویسی نشود. در خطای quota یا غیرفعال بودن storage، رابط همچنان در حافظه قابل ویرایش است.

فایل export دقیقاً همین ساختار را دارد و فیلد نسخه یا wrapper اضافی تولید نمی‌کند. همگام‌سازی میان چند tab وجود ندارد؛ آخرین ذخیره می‌تواند تغییرات tab دیگر را بازنویسی کند.
